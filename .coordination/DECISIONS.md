| O-9 | **A left-padded sequence encodes to NaN, so SASRec retrieves nothing for any history shorter than 50.** In `eval()` mode PyTorch takes a fused attention path that returns NaN for a query position whose keys are all masked; the first position of every left-padded sequence is exactly that, and the NaN propagates through the second block into the real positions. Verified on the pinned artifact `a11af5ed…`: histories of length 1/3/12/49 return **0** candidates, length 50 returns 500. Training mode does not take that path, which is why the model trained correctly and why nothing caught it. `build_index()`'s `.eval()` (commit 1d189a8, correct in intent — dropout must be off for deterministic retrieval) is what exposed it. **Every recorded SASRec number was measured under this**, so all of them *understate* the retriever: users and positives with 10-49 items of history got an empty slate from the learned path rather than a worse one. Affected: ADR 0016's retrieval verdict (+16.57% warm recall@500), step 1's dropped-positive counts, and all four PR #151 arms. | **Fix it, but not inside Rung 3, and re-measure the line as its own work item.** The remedy is one line — `torch.backends.mha.set_fastpath_enabled(False)` reproduces the training-mode path and removes the NaN — but it also moves full-length results by ~2.4e-7, so it is not a no-op on anything already recorded. Doing it inside increment 1 would be wrong twice over: the incumbent (1b, `566f5309…`) was measured under the defect, so fixing one side only would confound the ranker comparison with a retrieval change — exactly what ADR 0018 forbids — and it would invalidate `docs/results.md`, ADR 0016 and the roadmap Rung 2 row, which is a bigger re-measurement than the rung. Increment 1 therefore ships against the defect on both sides, where the comparison stays internally valid: identical candidates, identical groups, two columns different. The fix then lands as its own PR with a re-run of the retrieval gate and of 1b, and the expectation is that **SASRec's measured advantage grows**. Pinned meanwhile by `tests/feature_parity/test_sasrec_features_match_recomputed.py::test_left_padded_sequences_encode_to_nan_today` so it cannot be rediscovered by accident. | Opus failover D (increment 1) | **Orchestrator ruling 2026-09-05: recommendation accepted.** Increment 1 ships against the defect on both sides. The fix + re-measurement is W17 (Megatron, after the two-tower diagnostic): `set_fastpath_enabled(False)` in the shared encoder path, a test that a length-1 and length-49 history return 500 candidates, re-run the retrieval gate (`a11af5ed…` vs `4b342e87…`) and bundle 1b, dated notes on ADR 0016 / results / roadmap.
