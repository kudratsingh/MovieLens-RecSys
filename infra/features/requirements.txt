# Dependencies for the Feast feature server and the model sidecar.
#
# Exact pins, not floors. lightgbm is the one that matters most: the booster
# this image trains and the booster it later loads have to be produced by the
# same version for the reproducibility check on the serving bundle to mean
# anything. The versions below are the ones the reviewed
# `movielens-recsys/features:demo` image resolved; refresh them deliberately by
# rebuilding and reading `pip freeze` out of the new image. uvicorn is held at
# the version Feast's own dependency range resolves to, which is older than the
# API image's — the two images are pinned independently on purpose.
# alembic is not here to run migrations — the release job in the API image owns
# those. It is here so `bootstrap materialize --wait-for-schema` can read this
# image's own migration set: without it the fence cannot tell "the database is
# behind" from "the database is ahead of this image", and a rollback's
# pre-deploy would wait out its whole timeout and fail the deploy. Pinned to
# the same version as infra/api/requirements.txt so both images agree on what
# a revision graph is.
# torch and faiss are here because the model sidecar loads a SASRec encoder and
# rebuilds its exact FAISS index at startup (ADR 0013's bundle, O-12). Two things
# about these three lines are load-bearing rather than stylistic.
#
# The `--extra-index-url` and the `+cpu` local version are the pin. On linux/amd64
# a plain `torch==2.12.0` resolves to the default PyPI wheel, which bundles the
# CUDA runtime and drags in a set of `nvidia-*` packages — roughly an order of
# magnitude larger than the CPU build, on an image ADR 0013 ships to a 40 GB box
# that has no GPU. macOS has no CUDA build at all, so a developer machine cannot
# reproduce that mistake; only the amd64 build can, which is why the image asserts
# on it rather than trusting the pin to be copied correctly next time.
#
# The API image must never gain any of this. It holds the serving contract modules
# and nothing that imports a model; `tests/unit/test_serving_image_imports.py` is
# what keeps that true.
--extra-index-url https://download.pytorch.org/whl/cpu
torch==2.12.0+cpu
faiss-cpu==1.14.3

alembic==1.19.1
feast[postgres,redis]==0.65.0
fastapi==0.141.1
lightgbm==4.7.0
psycopg2-binary==2.9.12
pydantic-settings==2.15.0
sqlalchemy==2.0.52
uvicorn[standard]==0.34.0
